# صدى (Sada) 3.6.0 — جودة النص العربي وتقوية أمنية

**صدى** تطبيق تفريغ صوتي وفيديو إلى نص، عربي أولاً، يعمل بالكامل على جهازك بنظام Windows
بدون إنترنت وبدون حساب. يعتني هذا الإصدار بجودة النص النهائي: يعيد 21 مصطلحاً لاتينياً شائعاً
كان المحرّك يكتبها بالحروف العربية، ويصلح ترقيم العربية، ويطبّق نفس القواعد داخل أداة القياس
حتى لا يُقاس شيء مختلف عمّا يراه المستخدم. كما ينقل إلى الشوكة القطع المناسبة من تدقيق أمني
أحدث في Vibe (CSP، Markdown آمن، تقييد روابط sada: والنماذج وyt-dlp، عزل المحرّك، وضابط
الإملاء)، ويوثّق قبول الآلة النظيفة وقرار التوقيع. لا تغيير في المحرّك (يبقى
**vibe-server v0.6.16-sada.1**) ولا في النماذج، وليس في الشوكة تحديث تلقائي أو قياس عن بُعد.

## التثبيت والترقية

1. شغّل **Sada_3.6.0_x64-setup.exe**. التثبيت لكل مستخدم في **%LOCALAPPDATA%\Sada\** ولا
   يحتاج صلاحيات مدير.
2. **تنبيه SmartScreen:** المثبّت غير موقّع رقمياً، فقد يظهر «Windows protected your PC». اضغط
   *More info → Run anyway* فقط للإصدار الرسمي بعد التحقق من البصمة. خيارات التوقيع وتكلفتها
   مسجّلة في docs/SIGNING.md.
3. الترقية من 3.5.0: شغّل المثبّت الجديد فوق القديم؛ الإعدادات والمشاريع والنماذج تبقى كما هي،
   ومحرّك التفريغ نفسه.
4. **Windows 10 بلا إنترنت:** ثبّت **WebView2 Evergreen Runtime** مسبقاً (Windows 11 يضمّه).
   مثبّت NSIS الافتراضي ينزّل WebView2 من الشبكة عند نقصه؛ التفاصيل في docs/ACCEPTANCE.md.

## ما في هذا الإصدار

- **استعادة المصطلحات اللاتينية في النص العربي:** 21 مصطلحاً تقنياً شائعاً يعيدها التطبيق إلى
  اللاتينية عندما يكتبها المحرّك بالحروف العربية: GPU، CPU، HTTP، HTTPS، HTML، PDF، SRT، VTT،
  JSON، API، FFmpeg، Whisper، URL، SQL، CSS، USB، VPN، Wi-Fi، GitHub وغيرها. القواعد تتعامل مع
  «ال» التعريف والأشكال المنفصلة والموصولة (مثل «الجيبيو» و«جي بي يو») وتعمل على كلمات كاملة
  فقط، قبل قواعد الترقيم العربي (، ؟ ؛) وإصلاح التباعد. القواعد **بلا إضافة أو حذف أو إعادة
  ترتيب** وأحادية التطبيق (النتيجة نفسها إن طُبّقت مرتين)، وتُطبّق على كل الأسطح: النص المباشر،
  المشاريع المحفوظة، الإملاء، تسليم الهاتف، وكل صيغ التصدير.
- **طابق بين التطبيق وأداة القياس:** ملف الحالات المرجعية
  benchmarks/arabic-asr/fixtures/arabic-postprocess-cases.json يتحقق منه الطرفان (TypeScript في
  التطبيق وبايثون في sadabench/postprocess.py)، فلا تنحرف قواعد القياس عن قواعد العرض. أُضيف
  جدول **App-level** إلى تقرير القياس: على المقاطع الحالية النتيجة مطابقة للخام (Turbo 19.46%
  وNemotron 17.12% WER) أي أن التحسين تنسيقي لا يغيّر دقة الكلمات — وهذا مسجّل كما هو بلا مبالغة.
- **تقوية أمنية من تدقيق Vibe v3.3.6:**
  - سياسة CSP للواجهة (لا سكربت أو اتصال بعيد، object-src ممنوع، asset/blob فقط للوسائط).
  - Markdown آمن: الصور لا تُحمَّل، روابط http/https تُفتح في المتصفح لا داخل نافذة التطبيق،
    والخطط الأخرى (javascript: وغيرها) معطلة.
  - روابط sada: تقبل **https فقط** ومن huggingface.co أو github.com، وتعرض الرابط كاملاً
    وتطلب التأكيد، وتأخذ الحجم وبصمة SHA-256 من الكتالوج المرفق؛ رابط مضيف آخر يُرفض.
  - تنزيل النماذج محصور داخل مجلد النماذج بامتداد .bin أو .gguf مع رفض المسارات النسبية و..‏
    وروابط المجلدات الرمزية، وعميل التنزيل يتبع https فقط وبحد 10 تحويلات.
  - تحديث yt-dlp لا يقبل عنواناً من الواجهة: يتحقق من صيغة الإصدار، يبني رابط GitHub بنفسه،
    ويتطلب ملف SHA2-256SUMS المنشور.
  - محرّك التفريغ يبدأ بمجلد عمل معزول وTEMP خاص بالتطبيق مع إزالة GGML_BACKEND_PATH، فلا
    تُعاد توجيه مسارات تحميل المكتبات.
  - الإملاء: type_text مقيّد بنافذة 30 دقيقة بعد انتهاء تسجيل، بسقف 50,000 حرف وإزالة محارف
    التحكم، فلا يمكن لبرنامج آخر استخدام التطبيق لإدخال لوحة مفاتيح عشوائي.
  - الجدول الكامل في docs/UPSTREAM-PATCHES.md §10، وما لم يُنقل (القياس عن بُعد، بناء اختبارات
    موجهة للوكلاء، هجرة مجلدات، توقيع كتالوج بعيد) مذكور صراحة.
- **قبول آلة نظيفة وقرار التوقيع:**
  - docs/ACCEPTANCE.md: إجراء قبول كامل لمثبّت على جهاز بلا أدوات تطوير: تثبيت بلا شبكة،
    WebView2، تفريغ offline، CPU fallback، خلفية AVX2/AVX، حالة SSE4.2 بلا AVX، Nemotron + VAD،
    روابط sada:، الإملاء، عزل المحرك، وجدول أدلة يسجّل ما نُفّذ فعلاً وما بقي.
  - docs/SIGNING.md: مقارنة خيارات التوقيع وتكلفتها (SignPath Foundation مجاني للمصادر المفتوحة،
    Azure Artifact Signing نحو 10 دولارات شهرياً، شهادات OV/EV) والتوصية بعدم الشراء قبل قرار
    المالك؛ سكربت scripts/sign.py الموروث جاهز للتوصيل لكنه يبقى معطلاً.
- **توثيق محدّث:** SECURITY.md (نسخة مدعومة 3.6.x + قسم الدفاعات في العمق)، وAGENTS.md (فهرس
  الوثائق وعدد الاختبارات)، وسجل CHANGELOG وROADMAP.

# English

**Sada (صدى)** is an Arabic-first, fully offline speech-to-text desktop app for Windows, forked
from [Vibe](https://github.com/thewh1teagle/vibe) (MIT). Version 3.6.0 is about the text users
see: the app now restores 21 common Latin technical terms that the engine wrote out in Arabic
letters, fixes Arabic punctuation spacing, and scores the same rules in the benchmark so what is
measured is what is shown. It also ports the relevant parts of a newer Vibe security audit (CSP,
safe Markdown, locked-down sada: links, model and yt-dlp download checks, engine process
confinement, and a dictation typing permit) and records the clean-machine acceptance procedure and
the code-signing decision. No engine change (still **vibe-server v0.6.16-sada.1**), no model
change, and the fork still has no updater, telemetry or account.

## Install and upgrade

1. Run **Sada_3.6.0_x64-setup.exe**. Per-user install into **%LOCALAPPDATA%\Sada\**; no admin
   rights needed.
2. **SmartScreen:** the installer is not code-signed, so Windows may show "Windows protected your
   PC". Choose *More info → Run anyway* only for the official release after verifying the hash.
   Signing options and costs are recorded in docs/SIGNING.md.
3. Upgrading from 3.5.0: run the new installer over the old one; settings, projects and models are
   kept and the transcription engine is unchanged.
4. **Offline Windows 10:** install the **WebView2 Evergreen Runtime** first (Windows 11 ships it).
   The NSIS installer's default mode downloads WebView2 from the network when it is missing; see
   docs/ACCEPTANCE.md.

## What is in this release

- **Latin term restoration in Arabic transcripts:** 21 common technical terms that the engine
  writes in Arabic letters are restored to Latin — GPU, CPU, HTTP, HTTPS, HTML, PDF, SRT, VTT,
  JSON, API, FFmpeg, Whisper, URL, SQL, CSS, USB, VPN, Wi-Fi, GitHub and more. The rules handle the
  Arabic definite article and both split and joined spellings (for example الجيبيو and جي بي يو)
  and only fire on whole words, before the Arabic punctuation rules (، ؟ ؛) and spacing repair.
  They are **lossless** (no word is added, removed or reordered) and idempotent, and apply to every
  surface: live text, saved projects, dictation, phone handoff and every export format.
- **Shared app/benchmark parity:** the fixture file
  benchmarks/arabic-asr/fixtures/arabic-postprocess-cases.json is asserted by both the TypeScript
  implementation in the app and sadabench/postprocess.py, so the scoring rules cannot drift from
  what users see. The benchmark report now has an **App-level** table next to the raw one: on the
  current clips it equals raw (Turbo 19.46%, Nemotron 17.12% WER), because this pass fixes
  presentation, not word accuracy — stated plainly instead of claiming an accuracy win.
- **Security hardening ported from Vibe v3.3.6:**
  - a Content-Security-Policy for the webview (no remote scripts or connections, object-src
    disabled, media only through the asset/blob protocols);
  - safe Markdown: images are not fetched, http/https links open in the system browser instead of
    navigating the app window, and other schemes (javascript: and friends) are inert;
  - sada: links accept **https only** on huggingface.co or github.com, show the whole URL and ask
    for confirmation, and take the expected size and SHA-256 from the bundled catalogue; any other
    host is refused;
  - model downloads must be a .bin/.gguf file directly inside the models folder (relative paths,
    .., symlinked destinations and .part symlinks rejected), and the download client follows https
    redirects only, at most ten;
  - yt-dlp updates never take a URL from the webview: the version tag is validated, the GitHub
    release URL is built by the app, and the published SHA2-256SUMS file is required;
  - the engine starts in its own canonical directory with the app's TEMP and with
    GGML_BACKEND_PATH removed, so library load paths cannot be redirected;
  - dictation: type_text only works within 30 minutes of a finished recording, is capped at
    50,000 characters and strips control characters, so another local program cannot turn the app
    into an arbitrary keystroke injector.
  - The full table is in docs/UPSTREAM-PATCHES.md §10, including what was deliberately **not**
    ported (telemetry, an agent-drivable test build, staging-folder migration, remote catalogue
    signing).
- **Clean-machine acceptance and code signing:**
  - docs/ACCEPTANCE.md: the full procedure for installing on a machine with no developer tools —
    offline install, WebView2, offline transcription, CPU fallback, AVX2/AVX builds, the AVX-less
    SSE4.2 case, Nemotron + VAD, sada: links, dictation and engine confinement — with an evidence
    table that says which rows were actually run.
  - docs/SIGNING.md: signing options and real costs (SignPath Foundation free for open source,
    Azure Artifact Signing about US$10/month, OV/EV certificates) and the recommendation not to buy
    before the owner decides; the inherited scripts/sign.py is ready to wire but stays disabled.
- **Docs refreshed:** SECURITY.md (supported version 3.6.x and the new defence-in-depth section),
  AGENTS.md (docs index and test counts), CHANGELOG and ROADMAP.

## Verification before release

- **Frontend:** pnpm test — 31 files / 193 tests passed; pnpm build succeeded (paraglide, tsc, then
  vite, about one minute for the final bundle); i18n audit passed.
- **Rust:** cargo test --release — 101 tests passed in the desktop app; cargo test --release -p
  vibe-server guard:: — 8 tests passed.
- **Python:** python -m unittest discover -s tests — 44 tests passed in benchmarks/arabic-asr
  (including the shared postprocess cases).
- **New security tests:** media URLs, download destinations, yt-dlp version tags, the SUMS file,
  the typing permit and control-character scrubbing, safe Markdown, and sada: links (7 tests).
- The installer is produced by CI from the same source; its size and SHA-256 are recorded in
  docs/VERIFICATION.md after the release.

## Known limitations

- The installer is not code-signed, so SmartScreen may warn until one of the signing programmes in
  docs/SIGNING.md is adopted.
- Offline Windows 10 needs the WebView2 Runtime installed beforehand; the installer does not bundle
  it yet.
- Term restoration is presentation-only (no words added) and does not change WER; the unmeasured
  dialect slices are unchanged.
- SSE4.2-only CPUs without AVX cannot run the engine (both bundled CPU backends require AVX): the
  app shows a guidance error pointing to Settings → Advanced instead of crashing silently.
- The clean-machine rows (B–E) are a documented procedure not yet executed because the machines are
  not available; docs/ACCEPTANCE.md and docs/VERIFICATION.md say so explicitly.
