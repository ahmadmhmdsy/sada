# صدى (Sada) 3.8.0 — توزيع أوثق وبوّابة انحدار

**صدى** تطبيق تفريغ صوتي وفيديو إلى نص، عربي أولاً، يعمل بالكامل على جهازك بنظام Windows بدون
إنترنت وبدون حساب. هذا الإصدار **إصدار توزيع وثقة** لا إصدار ميزات: المحرّك (vibe-server
v0.6.16-sada.1) والنماذج والكتالوج وسلوك الواجهة مطابقة لـ3.7.0. ما تغيّر هو طريقة الوصول إلى
التطبيق والثقة به: مثبّت ثانٍ لـWebView2 يعمل **دون اتصال**، ومسار توقيع رقمي **جاهز لكن معطّل**
بقرار المالك (تبقى الإصدارات غير موقّعة ما دام المشروع مفتوح المصدر فقط)، وبوّابة آلية تمنع انحدار
دقّة التعرّف، ووثيقة جهوزية تشغيل صريحة. لا تحديث تلقائي ولا قياس عن بُعد ولا حساب.

## التحميل

| الملف | الوصف |
| --- | --- |
| **Sada_3.8.0_x64-setup.exe** | مثبّت Windows x64 الافتراضي (NSIS، نحو 45 ميغابايت، غير موقّع رقمياً) |
| **Sada_3.8.0_x64-setup-offline.exe** | مثبّت **دون اتصال** لـWebView2 (نحو 250 ميغابايت، نفس التطبيق) |
| **SHA256SUMS.txt** | بصمة SHA-256 للملفَّين معاً |
| **THIRD-PARTY-NOTICES.md** · **NOTICE** · **LICENSE** | الترخيص والإسناد وإشعارات الأطراف الثالثة |

تحقّق من الملف بعد التنزيل (PowerShell):

    Get-FileHash .\Sada_3.8.0_x64-setup.exe -Algorithm SHA256
    Get-FileHash .\Sada_3.8.0_x64-setup-offline.exe -Algorithm SHA256
    # قارن الناتج بسطرَي الملفَّين في SHA256SUMS.txt

## التثبيت والترقية

1. شغّل Sada_3.8.0_x64-setup.exe إن كان جهازك يتصل بالإنترنت (يُنزّل WebView2 عند الحاجة).
   شغّل Sada_3.8.0_x64-setup-offline.exe إن كان جهاز Windows 10 بلا إنترنت ولم يشغّل تطبيقاً
   حديثاً من قبل: يضمّن مثبّت WebView2 كاملاً فيكفي ملف واحد للتطبيق والواجهة.
2. التثبيت لكل مستخدم في %LOCALAPPDATA%\Sada\ ولا يحتاج صلاحيات مدير.
3. **تنبيه SmartScreen:** المثبّت غير موقّع رقمياً (قرار المالك 2026-11-18)، فقد يظهر
   «Windows protected your PC». اضغط *More info → Run anyway* فقط للإصدار الرسمي بعد التحقق من
   البصمة (docs/SIGNING.md).
4. **متطلب VC++:** مثبّت صدى يثبّت حزمة VC++ 2015-2022 تلقائياً من مايكروسوفت إن كانت ناقصة أو
   أقدم من 14.40. على جهاز بلا إنترنت نهائياً، ثبّت vc_redist.x64.exe مسبقاً (أو ثبّت WebView2
   أولاً فهو يجلب متطلباته).
5. الترقية من 3.7.0 أو أقدم اختيارية: لا تغيير سلوكي، والإعدادات والمشاريع والنماذج تبقى كما هي.

## ما في هذا الإصدار

- **مثبّت WebView2 دون اتصال (أصل ثانٍ):** يُبنى من نفس المصدر بملف إعداد
  desktop/src-tauri/tauri.offline.conf.json الذي يضبط webviewInstallMode = offlineInstaller،
  فيضمّن مثبّت WebView2 Evergreen داخل ملف NSIS. المثبّت الصغير الافتراضي (~45 ميغابايت) يبقى
  الخيار الأول؛ الكبير (~250 ميغابايت) لمن لا يستطيع الاتصال. الملفان للتطبيق نفسه وبصمتان
  منفصلتان في SHA256SUMS.txt. هذا يغلق الجزء الأكبر من #17 (يبقى تنفيذ صفوف القبول B–E).
- **توقيع رقمي مؤجّل ومهيّأ:** قرار المالك البقاء على إصدارات غير موقّعة ما دام المشروع مفتوح
  المصدر فقط. سير الإصدار أصبح يدمج ملف tauri.windows.signing.conf.json ويشغّل scripts/sign.py
  فقط عندما يكون متغيّر المستودع SIGNING_ENABLED مساوياً true، ثم يتحقق من توقيع كل ملف قبل
  النشر. بدون المتغيّر لا يتغيّر شيء: لا أسرار ولا uv ولا خطوة توقيع. خطوات التفعيل والبديل
  (SignPath / Azure) موثّقة في docs/SIGNING.md، و#18 يبقى مفتوحاً لتقديم الطلب.
- **بوّابة انحدار لدقّة التعرّف:** أمر جديد: python -m sadabench compare --baseline <نتيجة>
  --candidate <نتيجة> يعيد حساب الدرجات بنفس المقاييس ويقارن WER إجمالاً وكل شريحة؛ يفشل (رمز
  خروج 1) إذا تجاوز التدهور **1.0 نقطة** عن الأساس الملتزم به، ويعطي رمز 2 لملفات غير قابلة
  للمقارنة (مقاطع أو نصوص مرجعية أو شرائح مختلفة أو نموذج ناقص). الأساس هو
  results/results-2026-11-18-v2.json: مقارنة الأساس بنفسه تعطي 0.00 في كل الخلايا، واختبار
  يدوي بحذف نصوص خمسة مقاطع خليجية/تقنية أعطى +5.76 نقطة إجمالاً و+22.50 على الخليج (فشل كما
  يجب). للأمر 10 اختبارات جديدة (62 لبايثون إجمالاً) ويُشغّله CI على التقرير الملتزم به.
- **بيان جهوزية التشغيل:** docs/PRODUCTION-READINESS.md يجيب بصراحة عن «هل هو جاهز للإنتاج؟»:
  حكم لكل جمهور (فرد/فريق صغير: جاهز بشروط؛ نشر مؤسسي مُدار: ليس بعد)، وأدلة لكل ادعاء وفجوات
  مسماة (توقيع، صفوف B–E، العراقي/الشامي، لا دعم رسمي، لا نسخ احتياطي مدمج، لا تشفير للقرص).
  العربية والخلاصة في آخر الوثيقة.
- **تنظيف وثائق:** BUILDING.md يشرح مثبّتَي Windows وخطوات الإصدار الصحيحة، README/README.ar
  يشرحان اختيار الملف وحدود SmartScreen وVC++، SIGNING.md يوثّق القرار والتفعيل، وخُفِّضت أرقام
  الطريق القديمة (19.46% لـ60 مقطعاً) إلى أرقام 90 مقطعاً وسمّي سجل المهام بوضوح.

# English

**Sada (صدى)** is an Arabic-first, fully offline speech-to-text desktop app for Windows, forked
from [Vibe](https://github.com/thewh1teagle/vibe) (MIT). Version 3.8.0 is a **distribution and
trust release, not a feature release**: the engine (**vibe-server v0.6.16-sada.1**), models,
catalogue and UI behaviour are identical to 3.7.0. What changed is how you get the app and how much
you can verify about it: a second installer that works **fully offline** (WebView2 embedded), a code
signing pipeline that is **staged but dormant** (releases stay unsigned while the project is
open-source-only, by owner decision), an automatic **regression gate** so Arabic accuracy cannot rot
silently, and an explicit production-readiness statement. No updater, telemetry or account.

## Download

| File | What it is |
| --- | --- |
| **Sada_3.8.0_x64-setup.exe** | Default Windows x64 installer (NSIS, about 45 MB, not code-signed) |
| **Sada_3.8.0_x64-setup-offline.exe** | **Offline** WebView2 installer (about 250 MB, same app) |
| **SHA256SUMS.txt** | SHA-256 of both installers |
| **THIRD-PARTY-NOTICES.md** · **NOTICE** · **LICENSE** | Licence, attribution and third-party notices |

Verify the downloads (PowerShell):

    Get-FileHash .\Sada_3.8.0_x64-setup.exe -Algorithm SHA256
    Get-FileHash .\Sada_3.8.0_x64-setup-offline.exe -Algorithm SHA256
    # compare with the two lines in SHA256SUMS.txt

## Install and upgrade

1. Run **Sada_3.8.0_x64-setup.exe** if the machine can reach the network (it fetches WebView2 when
   needed). Run **Sada_3.8.0_x64-setup-offline.exe** if the target is an offline Windows 10 machine
   that has never run a modern app: it embeds the full WebView2 installer, so one file covers the
   app and the runtime.
2. Per-user install into %LOCALAPPDATA%\Sada\; no admin rights needed.
3. **SmartScreen:** the installer is not code-signed (owner decision, 2026-11-18), so Windows may
   show "Windows protected your PC". Choose *More info → Run anyway* only for the official release
   after verifying the hash (docs/SIGNING.md).
4. **VC++ requirement:** Sada's installer installs the VC++ 2015-2022 runtime from Microsoft when it
   is missing or older than 14.40. On a machine with no network at all, install vc_redist.x64.exe
   beforehand (or install WebView2 first, which pulls its dependencies).
5. Upgrading from 3.7.0 or older is optional: there is no behaviour change; settings, projects and
   models are kept.

## What is in this release

- **Offline WebView2 installer (second asset):** built from the same source with
  desktop/src-tauri/tauri.offline.conf.json, which sets webviewInstallMode = offlineInstaller so the
  WebView2 Evergreen installer is embedded in the NSIS file. The small default installer (~45 MB)
  stays the first choice; the large one (~250 MB) is for machines that cannot connect. Both are the
  same app with separate SHA-256 lines in SHA256SUMS.txt. This closes the main part of #17 (running
  acceptance rows B–E remains).
- **Signing staged, dormant:** the owner decided to keep releases unsigned while the project is
  open-source-only. The release workflow now merges tauri.windows.signing.conf.json and runs
  scripts/sign.py only when the repository variable SIGNING_ENABLED is true, then verifies every
  asset's Authenticode signature before publishing. With the variable unset nothing changes: no
  secrets, no uv, no signing step. The switch-on procedure and the SignPath/Azure alternatives are
  documented in docs/SIGNING.md; #18 stays open for the application itself.
- **Benchmark regression gate:** new command python -m sadabench compare --baseline <results>
  --candidate <results> re-scores both runs with the same scorer and compares WER overall and per
  slice. It fails (exit 1) when the candidate is worse than the committed baseline by more than
  **1.0 pp**, and exits 2 for incompatible runs (different clips, changed reference transcripts or
  slice labels, or a missing model). The baseline is results/results-2026-11-18-v2.json:
  self-comparison gives 0.00 everywhere, and a manual check that blanked five Gulf/technical clips
  failed correctly with +5.76 pp overall and +22.50 pp on the Gulf slice. The command has 10 new
  unit tests (62 Python tests total) and CI exercises it on the committed report.
- **Production-readiness statement:** docs/PRODUCTION-READINESS.md answers "is it production ready?"
  per audience (individual/small team: ready with conditions; managed enterprise deployment: not
  yet), with evidence links and named gaps (signing, acceptance rows B–E, Iraqi/Levantine coverage,
  no support contract, no built-in backup or disk encryption). An Arabic summary closes the
  document.
- **Documentation cleanup:** BUILDING.md explains both Windows installer variants and the correct
  release steps, README/README.ar explain which file to pick plus SmartScreen and VC++ limits,
  SIGNING.md records the decision and the switch-on procedure, and the roadmap's stale 60-clip
  numbers (19.46%) were replaced with the 90-clip figures.

## Known limitations

- **The installer is not code-signed**, so SmartScreen may warn until the staged signing path is
  enabled (docs/SIGNING.md, owner decision).
- **The offline WebView2 installer does not embed the VC++ runtime**; the installer downloads it when
  missing. On a fully offline machine, install vc_redist.x64.exe first.
- **Iraqi and Levantine remain unmeasured.** The Gulf and technical slices are scripted,
  code-switched speech, not spontaneous dialect speech; the Gulf slice is Saudi only and the
  technical slice is Egyptian only.
- 15-clip slices give wide confidence intervals: treat slice deltas below ~2 pp as unresolved unless
  a bootstrap says otherwise.
- There is no auto-update: users download the next release deliberately (a privacy feature that is
  also an operational burden).
- There is no app behaviour change in 3.8.0; users who do not need the new installer asset or the
  documentation can stay on 3.7.0.
