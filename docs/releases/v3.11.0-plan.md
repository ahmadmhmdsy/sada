# Sada v3.11.0 — release plan (internal)

**Status: planning, started 2026-11-22. No version bump, tag or release has been made.** This is the
working plan for the next release. The owner approves the scope, the five-user gate and the tag when the
gates in section 2 are green. The previous release record is [v3.10.0.md](v3.10.0.md).

## 1. Theme and scope

Roadmap slot: **v3.11.0 — P7: parity, proof & platform** (planned 2027-01-15 in ROADMAP; it moves
earlier only when the gates pass). It ships only what evidence supports: no new engine, no TTS/S2S claim.

Already on master since v3.10.0 (must be in the release):

- 20 dependency PRs merged 2026-11-21 plus the coordinated **utoipa 5 to 6** server upgrade (#68, `c2b8012`).
- Workflow bumps: actions/setup-node 4 to 7, github/codeql-action 3 to 4, actions/configure-pages 5 to 6,
  astral-sh/setup-uv 5 to 7, actions/attest-build-provenance 2 to 4.
- Docs and review records, and the **CI server build+test job** (PR #69, merge once its run is green).

Gated, not on master yet:

- **#53** Tauri runtime jump (tauri 2.10.3 to 2.12.7, wry 0.54.2 to 0.57.3, tao 0.34.6 to 0.37.3,
  notification plugin 2.3.3 to 2.8.1, 57 packages). The Tauri CLI 2.12 enforces npm/Rust alignment, so the
  lockfile-only bump could not bundle; `65973b3` aligns the stack (`@tauri-apps/api` 2.12.5,
  `@tauri-apps/plugin-notification` 2.8.1, `@tauri-apps/cli` ~2.12.6, `tauri-plugin-opener` 2.7.3).
  Status 2026-11-22: NSIS installer built locally, CI green; only the owner clean-machine install and the
  merge go-ahead remain.
- P7 features FC-2/FC-3/FC-4 per P7-PLAN, only as the five-user gate and evidence allow.

Explicit non-goals: engine or model change, TTS/speech-to-speech, auto-updater, telemetry/accounts,
Linux/macOS builds, code signing (owner decision A5), the 4.0 "Echo" identity (gated by the five-user test).

## 3. Work sequence

**Phase A — close the dependency train (agent, now)**

1. Finish the #53 gate. The Tauri CLI 2.12 enforces npm/Rust version alignment, and #53 is a lockfile-only
   bump, so the first installer attempt failed the check: tauri 2.12.7 vs `@tauri-apps/api` 2.10.1,
   tauri-plugin-notification 2.8.1 vs `@tauri-apps/plugin-notification` 2.3.3, tauri-plugin-opener 2.5.3 vs
   `@tauri-apps/plugin-opener` 2.7.3. Align the npm side (`@tauri-apps/api` 2.12.5, plugin-notification
   2.8.1), bump tauri-plugin-opener to 2.7.3 in the lockfile, then build the NSIS installer again, verify the
   artifact set and sidecar, push the alignment to the PR branch and wait for CI green.
2. Merge #69 when its run is green; confirm the server job is green on master.
3. Open `chore/release-prep-3.11` for G4 (sidecar suffix bump, attestation subject, docs sync in
   BUILDING / AV-EDR / SECURITY-WHITEPAPER / ACCEPTANCE); wait for CI.

**Phase B — owner (blocking)**

4. Run the five-user gate with the GATE-KIT and send the result.
5. Decide scope (FC-4 in or out), approve the #53 merge after the clean-machine test, and set the date.

**Phase C — version bump (agent)**

6. Bump the version in `desktop/src-tauri/tauri.conf.json` and `desktop/src-tauri/Cargo.toml`; update
   `CITATION.cff` (version + date-released), `README.md` and `README.ar.md`, `llms.txt`, `site/index.html`,
   `site/en/index.html`, `site/llms.txt`, and any current-version string in `ROADMAP.md`/`docs`.
7. Write `docs/releases/v3.11.0.md` (Arabic-first, same structure as v3.10.0: download table, install and
   verify, what is in this release, honesty note) and the `CHANGELOG.md` entry.
8. Run `chore ci`, the translation checks and the docs checks; push to master; wait for CI and Docs green.

**Phase D — tag and publish (owner go, then agent)**

9. Create an annotated tag `v3.11.0` on the verified commit and push it. That push starts the Release
   workflow — **never dispatch `release.yml` against an older tag**, and never reuse `v3.10.0`.
10. Watch the Release workflow: three installers (default NSIS, offline-WebView2 NSIS, per-machine MSI),
    `SHA256SUMS.txt`, CycloneDX SBOM, attestation. Verify with
    `./scripts/verify-release.ps1 -Version 3.11.0 -Download` (hash + `gh attestation verify`).
11. Verify the published release body matches `docs/releases/v3.11.0.md`; record sizes/hashes; update
    ACCEPTANCE, PRODUCTION-READINESS, OWNER-ACTIONS (like A14) and ROADMAP; run the clean-machine rows (A8).

## 4. Risks and rollback

- **Release workflow failure after build**: re-run the workflow for the same tag if nothing was published;
  if a bad release exists, delete release and tag, fix and re-tag the corrected commit (a published release
  cannot be edited into a different commit).
- **#53 regression**: the PR is a lockfile-only bump, so rollback is a single revert of `c2b8012`-style squash
  plus a rebuilt installer; the installer gate and the owner smoke test are the protection.
- **setup-uv 7 / attest v4 behavior unknown until the first real publish**: watch those steps; fallback is a
  hotfix workflow commit and a patch release (3.11.1), not a silently broken 3.11.0.
- **Sidecar/SBOM mismatch**: the SBOM `sidecarVersion` and AV-EDR must both say `v0.6.16-sada.2`; verify before
  announcing.
- **Scope creep**: anything not passing evidence moves to 3.12.
