# صدى (Sada) 3.11.0 — تحديث الاعتماديات وتقوية الإصدار

هذا إصدار **صيانة وتقوية إصدار**، لا إصدار ميزات: لا تغيير في الواجهة ولا في المحرّك ولا في
النماذج ولا في سلوك التفريغ. يحدّث الإصدار شجرة الاعتماديات (عشرون تحديثاً من Dependabot إضافة
إلى ترقية utoipa 6 المنسّقة)، ويضيف مهمة بناء واختبار لمحرّك التفريغ في التكامل المستمر، ويقوّي
سلسلة التوريد: نسخة المحرّك المضمّن صارت `v0.6.16-sada.2` لتمييز بناء المحرّك، وقائمة
`SHA256SUMS.txt` صارت مشمولة ببصمة البناء (attestation) إلى جانب المثبّتات وحزمة SBOM.

**ملاحظة الصدق نفسها تنطبق على هذا الإصدار:** المثبّتات ما زالت **غير موقّعة رقمياً**، ولا يوجد
تحديث تلقائي ولا قياس عن بُعد ولا حساب. **بوابة الخمسة مستخدمين لم تُجرَ بعد**، فهذا الإصدار لا
يدّعي أي تحسين مُقاس في الاستخدام، ولا يضم أي عمل من الموجة الثانية ولا هوية «الصدى» 4.0.

## التنزيل

| الملف | ما هو |
| --- | --- |
| **Sada_3.11.0_x64-setup.exe** | مثبّت Windows x64 الافتراضي (NSIS، لكل مستخدم، غير موقّع رقمياً) |
| **Sada_3.11.0_x64-setup-offline.exe** | مثبّت **دون اتصال** لـWebView2 (نفس التطبيق) |
| **Sada_3.11.0_x64_en-US.msi** | مثبّت **لكل جهاز** (WiX) للنشر المُدار عبر Intune/SCCM/GPO |
| **SHA256SUMS.txt** | بصمة SHA-256 لكل ملف، وهي نفسها مشمولة ببصمة البناء منذ 3.11.0 |
| **sbom-cyclonedx.json** | حزمة برمجيات CycloneDX (SBOM) |
| **THIRD-PARTY-NOTICES.md** · **NOTICE** · **LICENSE** | الترخيص والإسناد وإشعارات الأطراف الثالثة |

تحقّق من التنزيل (PowerShell):

    # 1) البصمات
    Get-FileHash .\Sada_3.11.0_x64-setup.exe -Algorithm SHA256
    # قارنها بالسطر المطابق في SHA256SUMS.txt
    # 2) بصمة البناء (GitHub CLI)
    gh attestation verify .\Sada_3.11.0_x64-setup.exe --repo alshahia/sada
    # أو استخدم سكربت التحقق الذي يفحص الاثنين في خطوة واحدة
    .\scripts\verify-release.ps1 -Version 3.11.0 -Download

## التثبيت والترقية

1. اختر الحزمة: المثبّت الافتراضي للاستخدام الفردي (بلا صلاحيات مدير)، أو MSI للنشر المُدار
   (صلاحيات مدير)، أو مثبّت WebView2 دون اتصال للأجهزة المعزولة.
2. التثبيت لكل مستخدم في %LOCALAPPDATA%\Sada\؛ وMSI يثبّت لكل جهاز في C:\Program Files\Sada\.
3. **SmartScreen:** الملفات غير موقّعة رقمياً (قرار المالك)؛ تحقّق من البصمة أو من بصمة البناء قبل
   تشغيلها. إرشادات القوائم المسموحة للمؤسسات في docs/AV-EDR.md.
4. الترقية من 3.10.0 أو أقدم: ثبّت البناء الجديد فوق القديم؛ تبقى الإعدادات والمشاريع والنماذج.
   لا يوجد تحديث تلقائي — يُنشر الإصدار التالي بواسطة المستخدم أو المدير.
5. النشر المُدار: انظر docs/ENTERPRISE-DEPLOYMENT.md (تثبيت صامت، اكتشاف، سياسة، تنظيف بيانات).

## ما في هذا الإصدار

- **تحديث الاعتماديات:** دُمجت **عشرون** ترقية من Dependabot في 20–21 نوفمبر 2026 (حزم Rust
  وnpm وسير عمل GitHub Actions: checkout 7، setup-node 7، cache 4،
  attest-build-provenance 4، configure-pages 6، codeql-action 4، وغيرها)، وانتقل توثيق
  OpenAPI في خادم المحرّك إلى **utoipa 6**. لا تغيير في سلوك المنتج.
- **تحديث حزمة Tauri:** انتقلت حزمة سطح المكتب من Tauri 2.10 إلى **2.12.7** (wry 0.57.3
  وtao 0.37.3) مع الحزم المتوافقة: `tauri-plugin-notification` 2.8.1 و`tauri-plugin-opener` 2.7.3
  و`@tauri-apps/api` 2.12.5 و`@tauri-apps/cli` 2.12.6. إصلاحات من المنبع فقط، ولا تغيير مقصود في
  الواجهة أو التفريغ. (بدأ #53 كتحديث لملف القفل وحده، لكن CLI 2.12 يفرض توافق npm مع Rust، فأُكملت
  الحزمة كوحدة واحدة وأُعيد تشغيل CI بالكامل.)
- **التكامل المستمر يبني المحرّك ويختبره:** مهمة `server` جديدة في `ci.yml` تشغّل
  `cargo check --all-targets` و`cargo test --release -p vibe-server` على كل تغيير، بعد جلب
  المكتبات الأصلية المثبّتة. تُغلق هذه المهمة الفجوة التي سمحت لانهيار حزمة المحرّك في #44 بأن
  يمر عبر CI ويفشل عند الإصدار فقط.
- **سلسلة التوريد:** المحرّك المضمّن صار يعرّف نفسه `v0.6.16-sada.2` (في سير الإصدار وحزمة SBOM
  ووثائق AV/EDR والأمن)، لأن 3.4.0–3.10.0 شحنت ثلاثة محرّكات مختلفة كلها تعرّف نفسها
  `v0.6.16-sada.1`؛ وتشمل بصمات البناء (Sigstore) الآن `SHA256SUMS.txt` إلى جانب المثبّتات
  الثلاثة وحزمة SBOM، فتصبح قائمة البصمات نفسها مشهودة.
- **تحديث رقم الإصدار إلى 3.11.0** في التطبيق وملفات Cargo وسجلات الموقع وREADME وllms
  وCITATION.

## ما ليس في هذا الإصدار (بقرار المالك)

- **لا ميزات واجهة جديدة ولا موجة ثانية:** الموجة الثانية (ومنها ملاحظات الاجتماعات FC-4)
  تنتظر نتيجة بوابة الخمسة مستخدمين وقرار المالك.
- **لا هوية «الصدى» (4.0):** الهوية الكاملة مؤجّلة إلى 4.0 وبعد البوابة.
- **لا تغيير في المحرّك أو النماذج أو سلوك التفريغ أو قائمة النماذج:** المحرّك يحمل الحاجز
  الأمني loopback نفسه، والبصمة الجديدة تميّز البناء فقط.
- **لا تغيير في المعمارية:** لا قياس عن بُعد ولا حساب ولا سحابة ولا تحديث تلقائي.

# English

**Sada (صدى)** is an Arabic-first, fully offline speech-to-text desktop app for Windows, forked
from [Vibe](https://github.com/thewh1teagle/vibe) (MIT). Version 3.11.0 is a **maintenance and
release-engineering release, not a feature release**: the UI, engine, models and transcription
behaviour are unchanged. It refreshes the dependency tree (twenty Dependabot updates merged on
20–21 November 2026 plus the coordinated utoipa 6 upgrade), adds a build-and-test job for the
transcription engine to CI, and hardens the supply chain: the bundled engine now reports
`v0.6.16-sada.2` so an installer’s engine build is identifiable, and the keyless build-provenance
attestations now cover `SHA256SUMS.txt` as well as the three installers and the SBOM.

The same honesty applies to this release: the installers are still **unsigned**, there is no
auto-updater, telemetry or account, and the limitations below still hold. The five-user gate has
**not been run yet**, so this release does not claim a measured usability improvement and contains
no Wave-2 work and no 4.0 "Echo" identity.

Verify the downloads (PowerShell):

    Get-FileHash .\Sada_3.11.0_x64-setup.exe -Algorithm SHA256
    # compare with the matching line in SHA256SUMS.txt
    # 2) Build provenance (GitHub CLI)
    gh attestation verify .\Sada_3.11.0_x64-setup.exe --repo alshahia/sada
    # or use the verification script, which checks both in one step
    .\scripts\verify-release.ps1 -Version 3.11.0 -Download

## Install and upgrade

1. Pick a package: the default installer for individual users (no admin), the MSI for managed
   deployment (admin rights), or the offline WebView2 installer for isolated machines.
2. Per-user install into %LOCALAPPDATA%\Sada\; the MSI installs per-machine into
   C:\Program Files\Sada\.
3. **SmartScreen:** the files are not code-signed (owner decision); verify the hash or the build
   provenance before running them. Allow-listing guidance for managed environments is in
   docs/AV-EDR.md.
4. Upgrading from 3.10.0 or older: install the new build over the old one; settings, projects and
   models are kept. There is no auto-update — the next release is deployed by the user or
   administrator.
5. Managed deployment: see docs/ENTERPRISE-DEPLOYMENT.md (silent install, detection, policy, data
   cleanup).

## What is in this release

- **Dependency refresh:** twenty Dependabot updates merged on 20–21 November 2026 (Rust crates,
  npm packages and GitHub Actions: checkout 7, setup-node 7, cache 4,
  attest-build-provenance 4, configure-pages 6, codeql-action 4 and others), plus the server’s
  OpenAPI stack moved to **utoipa 6**. No product behaviour change.
- **Tauri 2.12 stack:** the desktop runtime moved from tauri 2.10 to **2.12.7** (wry 0.57.3,
  tao 0.37.3) with the aligned plugin and CLI packages: `tauri-plugin-notification` 2.8.1,
  `tauri-plugin-opener` 2.7.3, `@tauri-apps/api` 2.12.5 and `@tauri-apps/cli` 2.12.6. Upstream
  fixes only; no intended UI or transcription change. The original lockfile-only PR (#53) could not
  pass the 2.12 CLI’s npm/Rust alignment check, so the whole stack was updated together and CI was
  re-run in full.
- **CI builds and tests the engine:** a new `server` job in `ci.yml` runs `cargo check
  --all-targets` and `cargo test --release -p vibe-server` on every change, after fetching the
  pinned native libraries. It closes the CI gap that let the engine breakage in #44 pass CI and
  fail only at release time.
- **Supply chain:** the bundled engine reports `v0.6.16-sada.2` (release workflow, SBOM, AV/EDR and
  security docs) because 3.4.0–3.10.0 shipped three distinct engines that all identified as
  `v0.6.16-sada.1`; and the keyless build-provenance attestations now cover `SHA256SUMS.txt` in
  addition to the three installers and the CycloneDX SBOM, so the hash list itself is attested.
- **Version bump to 3.11.0** across the app, Cargo manifests/lockfile and site/README/llms/CITATION
  metadata.

## What is deliberately not in this release

- **No new UI features and no Wave 2:** Wave 2 (including meeting notes, FC-4) waits on the
  five-user gate result and an owner decision.
- **The "Echo" 4.0 identity** is deferred to 4.0 after the gate; its brief
  `docs/design/echo-identity-4.0.md` is reference only.
- **No change to the engine, models, transcription behaviour or model catalogue:** the engine
  carries the same loopback guard, and the new build identity only distinguishes the build.
- **No architecture change:** no telemetry, account, cloud or auto-updater.

## Verification before release

- **Tests:** `pnpm test` = **34 files / 207 tests passed** on the release head; desktop
  `cargo test --release`; the CI server job (`cargo check --all-targets`,
  `cargo test --release -p vibe-server`) — all green on `master`.
- **Docs and metadata:** `node scripts/seo/check-seo.mjs` passed (titles, JSON-LD, social cards,
  hreflang, sitemap, README links, version references).
- **Artifacts:** built by the release workflow from the same source; sizes and SHA-256 are recorded
  in `docs/VERIFICATION.md` after the release, with an attestation check (including
  SHA256SUMS.txt) and a silent-install check of all three installers.

## Known limitations

- **The installers are not code-signed**, so SmartScreen may warn until the staged signing path is
  enabled (docs/SIGNING.md). There is no certification and no external audit.
- **The five-user gate has not been run yet:** 3.11 must not be read as a measured usability
  improvement until it completes. It is required before Wave 2 and 4.0.
- **The Windows screen-reader check has not been done:** an axe audit cannot see screen-reader
  behaviour.
- **Acceptance rows B–E are unexecuted** (offline Windows 10, CPU-only, AVX-only, SSE4.2 without
  AVX): the maintainer has no such hardware/VM.
- **No at-rest encryption of transcripts:** use BitLocker (or equivalent) for sensitive data.
- **The installed (Tauri) build was not re-audited for accessibility in this release:** there is no
  UI change; the 3.10.0 evidence stands.
