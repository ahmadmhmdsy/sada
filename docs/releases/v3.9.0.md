# صدى (Sada) 3.9.0 — ثقة مؤسسية وخيارات تحكّم

**صدى** تطبيق تفريغ صوتي وفيديو إلى نص، عربي أولاً، يعمل بالكامل على جهازك بنظام Windows بدون
إنترنت وبدون حساب. هذا الإصدار **إصدار ثقة وتحكّم** وليس إصدار ميزات للمحرّك: المحرّك
(vibe-server v0.6.16-sada.1) والنماذج والكتالوج وسلوك التفريغ كما هي. ما أُضيف هو البنية التي
تحتاجها الفرق والمؤسسات للثقة والتحكّم: **سياسة جهاز مُدارة** تفرض وضع عدم الاتصال وتعطّل
الذكاء الاصطناعي واستيراد الروابط وتنزيل النماذج، و**تخزين مفاتيح API عبر DPAPI**، و**سياسة
احتفاظ بالنصوص** مع حذف آمن، و**جرد كامل للاتصالات الشبكية**، و**حزمة ضمانات أمنية**، و**سلسلة
توريد موثّقة** (بيانات Provenance وSBOM)، و**مثبّت MSI لكل جهاز** للنشر المُدار. يبقى المثبّت
**غير موقّع رقمياً** بقرار المالك، ولا تحديث تلقائي ولا قياس عن بُعد ولا حساب.

## التثبيت والترقية

1. اختر الحزمة: المثبّت الافتراضي للمستخدم الفرد (لا يحتاج صلاحيات مدير)، أو مثبّت MSI للنشر
   المُدار (يحتاج صلاحيات مسؤول)، أو مثبّت WebView2 دون اتصال للأجهزة المعزولة.
2. التثبيت لكل مستخدم في %LOCALAPPDATA%\Sada\، وMSI لكل جهاز في C:\Program Files\Sada\.
3. **تنبيه SmartScreen:** الملفات غير موقّعة رقمياً (قرار المالك 2026-11-18)؛ تحقّق من البصمة أو
   من أصل البناء قبل التشغيل. دليل السماح في الأجهزة المُدارة في docs/AV-EDR.md.
4. الترقية من 3.8.0 أو أقدم: شغّل المثبّت الجديد فوق القديم؛ الإعدادات والمشاريع والنماذج تبقى.
   لا تحديث تلقائي — النشر التالي بقرار المستخدم أو المسؤول.
5. للنشر المُدار: راجع docs/ENTERPRISE-DEPLOYMENT.md (تثبيت صامت، كشف، سياسة، تنظيف بيانات).

## ما في هذا الإصدار

- **سياسة جهاز مُدارة (اختياري):** تُقرأ من HKLM\SOFTWARE\Sada\Policy (قيم DWORD) مع بديل
  ملف JSON في %ProgramData%\Sada\policy.json (أو SADA_POLICY_PATH للاختبار)؛ قيم السجل أولى
  والقيود تُجمع. القيم: OfflineMode (يمنع كل الشبكة بما فيها فحص الاتصال)، DisableAi،
  DisableUrlImport، DisableModelDownloads، TranscriptsDir (تثبيت مجلد النصوص). تُفرض في طبقة
  أوامر Rust عند كل إجراء وليس بإخفاء الواجهة فقط، وتُغطى باختبارات. أدوات: 
  scripts/enterprise/set-sada-policy.ps1 وclear-sada-policy.ps1 وREADME في
  docs/ENTERPRISE-DEPLOYMENT.md. الحد المعلن: مسؤول الجهاز المحلي يستطيع تعديل السياسة؛ استخدم
  صلاحيات Windows لضبط ذلك.
- **تخزين مفاتيح API عبر DPAPI:** مفاتيح Claude/OpenAI تُشفَّر لكل مستخدم Windows باستخدام
  CryptProtectData (نطاق المستخدم الحالي) وتُخزَّن كـ claudeApiKeyEnc/openaiApiKeyEnc في
  app_config.json؛ المفاتيح النصية القديمة تُهاجَر مرة واحدة عند الإقلاع ولا تُكتب نصاً صريحاً
  بعدها. نسخ الملف إلى حساب أو جهاز آخر لا يفكّ التشفير (إعادة إدخال المفتاح). الصناديق
  (Ollama) بلا مفاتيح.
- **احتفاظ بالنصوص وحذف آمن:** إعداد «الاحتفاظ بالنصوص» (0 = للأبد افتراضياً، 7/30/90/365 يوماً)
  مع حذف تلقائي عند الإقلاع وزر «احذف النصوص القديمة الآن»؛ الحذف محصور بمجلدات المشاريع
  وملفات transcript.vibe.json القديمة تحت مجلد النصوص، ولا يتبع روابط الرمز، ويبلغ عن العدد
  والبايتات المحرَّرة دون تسجيل محتوى.
- **جرد الاتصالات الشبكية:** docs/NETWORK.md (وعربي: docs/NETWORK.ar.md) يسرد كل مسار خارجي،
  مُطلِقه، بياناته، ومفتاح السياسة الذي يمنعه؛ ويؤكد أن نقل الصوت من الهاتف **معطّل نهائياً** في
  صدى (الأمر يرفض دائماً) وأن فحص الاتصال يتوقف تماماً في وضع عدم الاتصال.
- **حزمة الضمانات الأمنية:** SECURITY-WHITEPAPER.md، THREAT-MODEL.md، DATA-HANDLING.md،
  AV-EDR.md — مكتوبة لتكون مدخلات في مراجعة أمنية أو استبيان شراء، بحدود صريحة (لا تشفير للقرص،
  لا تدقيق خارجي، مثبّت غير موقّع).
- **سلسلة توريد موثّقة:** كل ملف إصدار يحصل على GitHub Build Provenance (Sigstore بلا مفاتيح)،
  ويُنشر ملف SBOM بصيغة CycloneDX، ويبقى SHA256SUMS.txt مسار التحقق دون إنترنت، مع سكربت
  scripts/verify-release.ps1 يجمع التحقق من البصمة والأصل في خطوة واحدة. التفاصيل في
  docs/SUPPLY-CHAIN.md.
- **مثبّت MSI لكل جهاز + عدة النشر:** يُبنى من desktop/src-tauri/tauri.enterprise.conf.json
  ويُنشر كأصل ثالث؛ تثبيت صامت msiexec /i ... /qn، كشف عبر الإصدار/السجل، إلغاء تثبيت، تنظيف
  بيانات المستخدم، وسياسة الجهاز — كلها موثقة في docs/ENTERPRISE-DEPLOYMENT.md مع سكربتات في
  scripts/enterprise/.
- **عمليات أمنية مستمرة:** سير عمل Security جديد (فحص RustSec لكل ملفات Cargo، فحص npm للإنتاج
  يفشل فقط عند ثغرات حرجة، CodeQL للواجهة)، وDependabot لـCargo/npm/actions/Python، وأهداف
  استجابة في SECURITY.md (إقرار 3 أيام عمل، إصلاح عالٍ 30 يوماً).

# English

**Sada (صدى)** is an Arabic-first, fully offline speech-to-text desktop app for Windows, forked
from [Vibe](https://github.com/thewh1teagle/vibe) (MIT). Version 3.9.0 is a **trust and control
release, not an engine feature release**: the engine (**vibe-server v0.6.16-sada.1**), models,
catalogue and transcription behaviour are unchanged. What it adds is the infrastructure teams and
organizations need to trust and control it: a **managed machine policy** that can enforce offline
mode and disable AI, URL import and model downloads, **DPAPI-protected API keys**, **transcript
retention** with safe purge, a complete **network egress inventory**, an **assurance pack**, a
**keyless supply chain** (build provenance attestations + CycloneDX SBOM), and a **per-machine MSI**
for managed deployment. The installers remain **unsigned** by owner decision, and there is still
no auto-updater, telemetry or account.

## Install and upgrade

1. Pick a package: the default installer for individual users (no admin), the MSI for managed
   deployment (admin rights), or the offline WebView2 installer for isolated machines.
2. Per-user install into %LOCALAPPDATA%\Sada\; the MSI installs per-machine into
   C:\Program Files\Sada\.
3. **SmartScreen:** the files are not code-signed (owner decision, 2026-11-18); verify the hash or
   the build provenance before running them. Allow-listing guidance for managed environments is in
   docs/AV-EDR.md.
4. Upgrading from 3.8.0 or older: install the new build over the old one; settings, projects and
   models are kept. There is no auto-update — the next release is deployed by the user or
   administrator.
5. Managed deployment: see docs/ENTERPRISE-DEPLOYMENT.md (silent install, detection, policy, data
   cleanup).

## What is in this release

- **Managed machine policy (opt-in):** read from HKLM\SOFTWARE\Sada\Policy (DWORD values) with a
  JSON fallback at %ProgramData%\Sada\policy.json (or SADA_POLICY_PATH for testing); registry
  values win and restrictions are OR-ed. Values: OfflineMode (blocks all network use, including the
  connectivity probe), DisableAi, DisableUrlImport, DisableModelDownloads, TranscriptsDir (pins the
  transcripts folder). The Rust command layer re-checks the policy on every guarded action, so
  hiding a control is never the only enforcement; the behaviour is covered by unit tests. Helper
  scripts: scripts/enterprise/set-sada-policy.ps1 and clear-sada-policy.ps1, documented in
  docs/ENTERPRISE-DEPLOYMENT.md. Stated boundary: a local administrator can change the policy; use
  Windows user rights/AppLocker to constrain that.
- **DPAPI key storage:** Claude/OpenAI API keys are encrypted per Windows user with
  CryptProtectData (current-user scope) and stored as claudeApiKeyEnc/openaiApiKeyEnc in
  app_config.json; legacy plaintext keys migrate once at boot and are never written back as
  plaintext. Copying the config to another account or machine does not decrypt the blobs (the key
  must be re-entered). Ollama has no key.
- **Transcript retention and safe purge:** a "keep transcripts for" setting (0 = forever, the
  default; 7/30/90/365 days) with an automatic purge at launch and a "delete old transcripts now"
  action. Deletion is limited to project folders and legacy transcript.vibe.json files under the
  transcripts folder, does not follow symlinks, and reports counts and freed bytes without logging
  content.
- **Network egress inventory:** docs/NETWORK.md (Arabic: docs/NETWORK.ar.md) lists every outbound
  path, its trigger, its payload and the policy switch that removes it; it records that phone
  handoff is **disabled unconditionally** in Sada (the start command always refuses) and that the
  connectivity probe stops completely under offline mode.
- **Security assurance pack:** SECURITY-WHITEPAPER.md, THREAT-MODEL.md, DATA-HANDLING.md and
  AV-EDR.md — written as inputs for a security review or procurement questionnaire, with explicit
  limitations (no at-rest transcript encryption, no external audit, unsigned binaries).
- **Documented supply chain:** every release asset gets keyless GitHub build provenance
  attestations (Sigstore), a CycloneDX SBOM is published, SHA256SUMS.txt remains the offline
  verification path, and scripts/verify-release.ps1 performs both checks in one step. Details:
  docs/SUPPLY-CHAIN.md.
- **Per-machine MSI and deployment kit:** built from desktop/src-tauri/tauri.enterprise.conf.json
  and published as the third asset; silent install msiexec /i ... /qn, detection by version/registry,
  uninstall, user-data cleanup, and machine policy are documented in
  docs/ENTERPRISE-DEPLOYMENT.md with scripts under scripts/enterprise/.
- **Ongoing security operations:** a new Security workflow (RustSec audit of every cargo lockfile,
  production npm audit that fails only on critical advisories, CodeQL for the frontend), Dependabot
  for Cargo/npm/actions/Python, and response targets in SECURITY.md (acknowledge in 3 business days,
  high-severity fix within 30 days).

## Known limitations

- **The installers are not code-signed**, so SmartScreen may warn until the staged signing path is
  enabled (docs/SIGNING.md, owner decision). There is no certification and no external audit.
- **Acceptance rows B–E are unexecuted** (offline Windows 10, CPU-only, AVX-only, SSE4.2 without
  AVX): the maintainer has no such hardware/VM. The script and runbook now exist:
  scripts/acceptance/run-row-b-e.ps1 and docs/VALIDATION-RUNBOOK.md.
- **Policy is enforced inside the app:** a local administrator can change HKLM; use Windows user
  rights/AppLocker to constrain that boundary.
- **No at-rest encryption of transcripts:** use BitLocker (or equivalent) for sensitive data; only
  the API keys are DPAPI-encrypted.
- **The MSI requires administrator rights** and needs the WebView2 runtime present (install WebView2
  first, or use the offline NSIS installer for clean/air-gapped machines).
- **Iraqi and Levantine remain unmeasured**, and 15-clip slices have wide confidence intervals; no
  accuracy claims are made beyond the published set.
- No auto-update: the next release is deployed deliberately (a privacy feature that is also an
  operational burden).
