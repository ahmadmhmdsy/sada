# Sada v3.12.0 — release plan (internal)

**Status: planning, drafted 2026-11-23. No version bump, tag or release has been made.** The scope is
not final: it depends on the five-user gate (G1) and the owner's scope call between the three options
in §2. The v3.11.0 maintenance cut shipped 2026-11-22 and moved the P7 M2 feature scope here
([v3.11.0-plan.md](v3.11.0-plan.md), [P7-PLAN.md](../P7-PLAN.md), [ROADMAP.md](../../ROADMAP.md)).

## 1. Theme and scope

Roadmap slot: the next feature release after v3.11.0. It carries everything that was deferred from
3.11 and everything the five-user gate unblocks — nothing more:

- **Wave 2 platform repairs** from the [UI/UX review](../UI-UX-REVIEW.md): error taxonomy end to end,
  export grouping (all nine formats kept), contextual enabled CTAs, one help/shortcuts screen, the
  version-row contrast fix, regenerated screenshots, and the RTL sidebar test plus its staging decision.
- **FC-4 — meeting-notes polish** ([#61](https://github.com/alshahia/sada/issues/61)): a finished
  auto-transcribed meeting produces a local summary/notes template; settings copy explains detection and
  auto-transcribe; works offline with a local model or clearly requires the user's AI setup.
- **FC-5 — translation/AI copy and QA** ([#62](https://github.com/alshahia/sada/issues/62)): state
  Whisper translate→English (medium/large, not turbo); document the local Ollama path; label AI output;
  no implication of an offline Arabic translation engine.
- **Optional, owner choice:** the first **Echo 4.0 identity** step as a preview only
  ([echo-identity-4.0.md](../design/echo-identity-4.0.md), option B in §2). No identity token, layout or
  logo change may merge before the owner approves the preview separately.

Already on master and assumed by this release: the v3.11.0 maintenance baseline (tag `c7acdc8`),
P7 FC-1 documentation, FC-2 (read-aloud FAIL) and FC-3 (subtitle burn-in PASS) evidence.

Explicit non-goals: engine or model change (and therefore no benchmark-gate obligation unless scope
changes), TTS/speech-to-speech and read-aloud claims, auto-updater/telemetry/accounts, Linux/macOS
builds, code signing (owner decision A5), live-caption UI while upstream ships no streaming mode (FC-6
— no fake captions), and any dialect-coverage claim before a licensed corpus exists (FC-7 /
OWNER-ACTIONS A10).

## 2. Scope options — owner decision after G1

| Option | Content | Release shape | Trade-off |
| --- | --- | --- | --- |
| **A — Gate-first (recommended default)** | Wave 2 repairs + FC-4 notes + FC-5 copy QA | normal feature release (3.12.0) | keeps the evidence chain: measure → fix → re-measure; no identity churn before the 4.0 decision |
| **B — Identity-first** | Echo 4.0 steps 1–3 as a build-flag preview (tokens, shell, motif; step 1 prepared in [#83](https://github.com/alshahia/sada/pull/83)); Wave 2 postponed to 3.13 | preview branch + owner review; small or no 3.12.0 feature payload | fastest visible identity, but mixes brand work with an unmeasured platform and delays the repairs the gate was designed to validate |
| **C — Engineering-only (fallback)** | Upstream Vibe 3.2.2 → 3.3.8 incremental port, engine-source parity first (speaker-label fix, issue #73) + Dependabot/CI upkeep; no UI feature | maintenance or minor release | keeps the fork current while the gate is delayed, but no UX progress |

**Recommendation:** A. Use C only if the gate is going to be delayed again, and B only if the owner
explicitly wants identity ahead of platform polish — in which case the preview still needs its own
approval before any in-app token change ships.

## 4. Work sequence

**Phase 0 — ungated preparation (agent, done 2026-11-23)**: gate kit refreshed to 3.11.0 with the
[GATE-RUN-3.11](../design/ui-decisions/GATE-RUN-3.11.md) run pack; this plan drafted; Dependabot grouping
[#72](https://github.com/alshahia/sada/pull/72) merged; upstream v3.3.8 assessed in
[UPSTREAM-REBASE-3.3.8.md](../UPSTREAM-REBASE-3.3.8.md) — engine source parity is a likely speaker-label
regression ([#73](https://github.com/alshahia/sada/issues/73), owner action A18); non-shipping Echo preview
in [#83](https://github.com/alshahia/sada/pull/83).

**Phase A — owner (blocking)**: run the five-user gate with the run pack and send the five-row result;
choose scope A, B or C; if B, review the Echo preview.

**Phase B — implementation (agent, after G2)**:

1. Scope the chosen option into a work list with one commit or PR per item; keep each item shippable
   behind the existing UI.
2. Wave 2 repairs with before/after screenshots and an axe pass on the changed states; FC-4/FC-5 with
   the claim-ledger and truth-editor review discipline from P7.
3. Echo identity, if B: tokens first (reversible, no layout), then shell, motif and secondary surfaces,
   each behind a build flag until the owner approves the whole set; do not touch the icon, installer
   artwork or OG cards in this release.
4. Run `pnpm test`, `pnpm build`, `node scripts/seo/check-seo.mjs`, `python scripts/check_i18n.py`.

**Phase C — version bump and notes (agent)**: bump the version, write the bilingual notes (same shape as
v3.11.0), update CHANGELOG and every "current version" reference, push, wait for CI and Docs green.

**Phase D — tag and publish (owner go, then agent)**: annotated tag, push (never dispatch
`release.yml` against an older tag), watch the workflow, verify with
`scripts/verify-release.ps1 -Version 3.12.0 -Download`, check the published body, record hashes in
VERIFICATION and close the release rows in OWNER-ACTIONS/ROADMAP.

## 5. Risks and rollback

- **Gate says partial/fail**: implement only the failing task as a patch release; retest with the next
  five participants; 3.12 scope does not start. Do not "fix forward" on unevidenced UI work.
- **Identity scope explosion**: the 4.0 brief caps the release at tokens → shell → motif → secondary
  surfaces; icon/installer artwork and dark theme are later, owner-approved steps. The token layer is one
  revert.
- **Upstream rebase conflicts**: keep the rebase in its own release/PR, never mixed with UI or identity;
  the assessment records the conflict hotspots and effort estimate.
- **Dependabot churn**: grouped PRs still need the same CI gate and per-PR revert discipline; major
  bumps stay individual.
- **Release workflow reuse**: same rules as 3.11 — fix and re-tag a corrected commit only if no release
  was published; never reuse an older tag.
